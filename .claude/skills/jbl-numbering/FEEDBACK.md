# 사용자 피드백 — 기록 방법과 누적 기록

## 피드백을 받으면(매번 이 순서)
1. 사용자 말을 **원문 그대로** `guide/피드백기록.md`에 한 줄(저장소 규칙) + 아래 '누적 기록'에 한 줄: `날짜 · 문제(id·주제) · 판정(승인/거절/부분) · 기제(왜 성공·실패 — 관문 번호) · 재사용 규칙 · 대체안이 실제로 사용자 승인됐는지`.
2. 세션에 판정 기록: `nb.py feedback 세션 ID --verdict approve|reject --text "사용자 말"` — 거절이면 그 문제는 다시 todo, 거절된 이야기는 실패 사례로만 남음(다시 내지 않음).
3. 사례 갱신: 승인 → `EXEMPLARS.md` A(성공) · 거절 → B(실패 — 기제와 고치는 방향). 사용자 승인 없이 A에 올리지 않는다.
4. 규칙이 새로 생기거나 바뀌면 `PRINCIPLES.md` 해당 관문·장치에 반영(옛 예시는 지우지 않고 합침). 검수 절차가 바뀌면 `REVIEW.md`.
5. 새 규칙을 **남은 todo와 아직 사용자에게 안 간 통과본**에 다시 적용(걸리면 todo로).
6. 보고 끝에 한 줄: "스킬에도 반영: PRINCIPLES n · EXEMPLARS A/B · REVIEW …".
이것은 버전 붙은 파일 갱신이지 모델 학습이 아니다 — 다음 세션은 이 파일들을 읽어서만 바뀐 규칙을 안다(그래서 커밋·푸시까지).

# 문제별 검수 절차(제작자 자체 검수 → 독립 블라인드 검수)

## 1. 자체 검수 — 문제마다, 저장 전에(생략 금지)
초안마다 아래를 실제로 해 보고, 결과를 검수 기록에 짧게 남긴다(`nb.py save … --review-file`).

1. **괄호 지우기(G1)**: 괄호를 다 지운 글을 소리 내듯 읽는다. 행동마다 "왜 이 일이 일어났지?"에 앞 문장이 답하는가. 목록·체크리스트 대사처럼 읽히면 실패.
2. **블라인드 복원(G2)**: 정답을 보지 않고 문제 + 괄호 지운 글만으로 항목을 **적는다**(순서는 G5). 항목마다 어느 단서 말에서 나왔는지(단서 → 항목) 짝을 적고, 다른 답으로 읽힐 위험이 있는 단서는 '위험'으로 표시(블라인드 검수가 그곳을 집중해서 봄). 내 의학 지식으로 '그냥 아는' 항목은 단서에서 나온 것으로 치지 않는다. 적은 목록을 정답과 견줘 빠짐·뒤바뀜·흐림을 표시.
3. **풀어쓰기 검사(G3)**: 이야기 전체가 정답 번역의 나열인가? 의학 절차·기전을 차례로 다시 말하는가? 기술 용어가 사람·물건으로 분장만 했나? 하나라도 '예'면 전제부터. 단서 하나가 의미 단서면 — 장면 안 일상 행동·사물이고 비틀림이 있는지(UV) 확인, 단순 직역 형용이면 그 단서만 바꿈.
4. **괄호 검사(G4)**: 괄호마다 원문 그대로의 최단 핵심어인가(도구가 원문 포함 여부·길이를 검사함). 괄호가 단서를 대신하지 않는가.
5. **완전·순서·숫자(G5)**: 빠진 항목 0 · 숫자·단위·방향 정확 · 순서 의미 있는 답은 순서 그대로 · 구별에 필요한 한정어(vertical·severe…)가 **제 단서**로 읽히나 · 소리 조각이 두 낱말에 쪼개져 있지 않나 · 항목 하나가 둘로 세어질 위험(만삭 + 수유 = pregnancy and nursing 하나).
6. **추가 암기(G6)**: 새 이름·약자 줄·암호가 생겼나 · 이야기 자체를 외워야 하나.
7. **길이(G7)**: 승인 예시(100~200자) 근처인가 · 더 줄일 곳.
8. **문제 고리(G8)**: 문제를 보면 이 장면이 떠오르나 · 같은 강의 다른 이야기와 헷갈리지 않나(관련 문제 목록으로 간섭 확인).
9. **대안 비교**: 버린 전제 중 가장 나은 것(초안까지 쓴 것)과 나란히 견줘 정말 이 안이 낫나.
10. **승인 기준 견주기**: 괄호 뺀 글을 CDS·D1·UV(EXEMPLARS A) 옆에 놓는다 — 같은 급인가? 관문은 다 넘어도 한 급 아래(길다·단서 반이 직역·장면이 덜 살아 있음)면 재창작, 안 되면 보류(이유 '기준 미달').

### 결함이 있으면
- 막힌 관문 + **원인 기제**를 한 줄로(예: "G3 — 3·4번 단서가 'pressure·time'의 번역").
- **국소 결함**(단서 하나·소리 순서·간섭 단어·인과 하나) → 그 단서만 다른 방식(소리↔숫자↔사물)으로 · 전제 유지 가능.
- **구조 결함**(사슬 없음·답 번역 전제·인물표·복원 2개 이상 실패·목록꼴) → 전제부터 새로.
- 표현만 다듬기·같은 단서 말 바꾸기·점수만 다시 매기기는 '재작업'이 아님.
- 구조 결함 재창작 3번에도 G1·G2·G3 중 하나가 막히거나 10번(승인 기준)에 못 미치면 **보류(hold)**: 이유와 최선안을 남기고 넘어감(결과 JSON에 안 들어감).

## 2. 검수 기록 틀(save --review-file에 넣는 글 — 짧게)
```
분해: 항목 n개(원문 순서) · 해설 제외: … · 한정어: … · 순서: 의미 있음/원문 유지/바꿈(이유)
전제: (고른 것 한 줄) | 버린 전제: ① … (이유) ② … (이유 — 초안까지 써 본 것 표시)
G1 자연성: 통과 — (괄호 뺀 흐름 한 줄)
G2 복원: 1 크루즈→Crouzon · 2 피자→Pfeiffer · … (항목 전부 · 빠짐 0 · 위험: 4번 '레스토랑'은 restoration 말고도 읽힘)
G3 리셋: 통과 — (번역·절차 재진술 없음 근거)
G4 괄호: 통과
G5 완전·순서·숫자: 통과 (항목 n/n)
G6 추가 암기: 없음
G7 길이: n자
G8 문제 고리: (문제어 → 장면)
대안 비교: (가장 나은 버린 안보다 나은 이유) · 승인 기준: CDS·D1·UV와 같은 급인가
재작업: (국소/구조 · 몇 번 · 무엇을 왜 바꿨나) | 판정: pass
```
도구는 `G2` 줄에 '단서→항목' 짝이 괄호 수만큼 없으면 통과 저장을 받지 않는다.

## 3. 독립 블라인드 검수(통과 후보를 내기 전에 — 필수 · 도구가 막음)

### 3-0. 기본 지시문 = '사용자 눈' 검수(10-11 — 복원 + 개연성 + 키워드 덩어리를 한 번에 · 정답 없이 · 병렬 3명)
> 너는 넘버링 스토리 독립 검수 담당이야(정답은 못 봄). 파일 하나만 읽어(다른 파일·웹 금지): <nb blind 출력 파일>
> 사용자가 만족한 기준 예시(괄호 뺀 꼴): EXEMPLARS A0 두 개(D1 · 캐릭터 만들기/플레이) — 한 장면 안에서 줄이 이어지는 문장처럼 흐르고, 소리·외래어·말장난 단서, 간결·강렬.
> 사용자가 싫어한 꼴: 정답 뜻을 우리말로 옮긴 말만 줄줄이(예: "재료 성질 / 남은 치아 양 / 예쁨 / 취향 / 돈") — 개연성 없는 키워드 덩어리.
> 문제마다: ① 복원(단서 → 항목 · 지식으로만 아는 건 '지식') ② 개연성(끊기는 줄) ③ 키워드 덩어리·번역 나열 줄 ④ 군더더기·더 강렬하게 할 곳 ⑤ pass/fail + 이유(항목 빠짐·지식·다른 답·키워드 덩어리·개연성 깨짐 중 하나라도면 fail). 결과는 파일로, 답은 "완료 pass n fail m" 한 줄.
- 받은 뒤: fail 문제마다 원인 기제 한 줄 → 국소/구조 재제작 → 다시 검수(새 담당). `nb blindres`로 기록. 검수 담당의 '군더더기·강렬' 제안은 pass여도 반영 검토.
제작자는 정답을 이미 알아서 G2를 후하게 본다. 그래서 통과 후보를 낸 뒤, **새 맥락의 다른 담당**(Agent 하나 · 이 스킬 파일은 읽지 않아도 됨)에게 다음만 준다:
`nb.py blind 세션 [--ids …]` 출력 = 문제 + 괄호를 뺀 스토리(정답 없음).

검수 담당 지시(그대로 붙여 쓰기):
> 각 문제마다 ① 이 이야기만 보고 떠오르는 정답 항목을 순서대로 적어(단서 말 → 항목 짝으로). ② 네 의학 지식으로만 아는 항목은 '지식'이라고 따로 표시해 — 단서에서 나온 것만 단서로 쳐. ③ 괄호 없이 읽을 때 어색하거나 끊기는 곳, 여러 답으로 읽히는 단서, 외워야 할 이름·약자를 짚어. ④ 1~5로 '이야기만으로 떠오름' 점수. 고치지 말고 보고만.

받은 뒤 제작자가 정답과 견줘 문제마다 기록: `nb blindres 세션 id,id --ok --note "5/5"` 또는 `--fail --note "3번 안 떠오름"`(실패 = 다시 todo · 같은 글은 다시 통과 저장 안 됨).
- 실패: 빠진 항목·'지식'으로만 나온 항목·다른 답으로 읽힌 단서 — 검수 담당 점수가 높아도 빠짐이 있으면 실패.
- 어색 지적만 있으면 제작자가 판정: G1 실패(인과 끊김·목록처럼 읽힘)면 실패, 취향 차이면 통과 + 노트.
- `nb export`는 독립 검수 통과(`--ok`)한 것만 낸다. Agent를 쓸 수 없는 환경이면 어쩔 수 없이 `--no-blind`(결과 note에 '독립 블라인드 검수 안 함 n개'가 붙음) — 사용자에게 그 사실을 알린다.
- 묶음 크기: 10~15문제씩 한 담당(맥락이 섞이지 않게). `nb blind`는 기본으로 아직 검수 안 한 통과본만 보여 줌(같은 이야기를 같은 담당에게 두 번 보이지 않게).

## 4. 판정 기호
- `pass` — 자체 검수(1) 통과. 독립 검수(3) `--ok`까지 받아야 결과 JSON에 들어감(사용자 승인 전까지는 '잠정').
- `hold` — 3번 전면 재창작에도 관문 미통과 · 정답 불명확 · 사용자 판단이 필요한 문제(이유 필수). 결과 JSON에 안 들어감(`out/hold.md`).
- `todo` — 아직/다시.
- `keep` — 사용자가 쓴 스토리가 있는 문제(손대지 않음).

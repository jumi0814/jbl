# 앞으로 — `/jbl-numbering 과목명`(이번에는 만들지 않음 · 설계만)

목표: `/jbl-numbering CONS`라고만 하면 그 과목 '내 넘버링' 문제를 불러와 제작·검수하고 JBL에 안전하게 반영.

## 걸림돌(지금 구조)
- 넘버링 원본은 **사용자 브라우저 localStorage**(`jblhub.v1.num.i.<과목>.<id>` — 기기마다 따로, IndexedDB 백업 비춤)에만 있다. 공개 저장소·GitHub Pages에는 없다(올리면 안 됨 — 사용자 글).
- Claude Code(맥 CLI든 클라우드든)는 그 브라우저 저장소를 직접 읽거나 쓸 수 없다. 억지로 쓰면(예: 브라우저 프로필 파일 직접 수정) 다른 탭·기기와 어긋나고 되돌리기가 없다 → **금지**.
- 사용자가 JBL을 여는 동안 같은 문제를 고칠 수 있다 → 쓰기는 반드시 지문(s0)·수정 시각(u) 비교 뒤, 사용자가 보는 미리 보기를 거쳐야 한다.

## 단계별 설계(안전한 것부터)
1. **(지금) JSON 다리** — 사용자가 내보내기 → 스킬 → 결과 JSON 붙여 넣기 → JBL 미리 보기·적용. 충돌은 JBL의 s0 비교·트랜잭션 적용이 막음.
2. **백업 파일 읽기(읽기 전용)** — 사용자가 JBL 백업 파일(dumpAll — 모든 `num.*` 포함)을 주면 `/jbl-numbering CONS 백업.json`이 그 과목 문제를 내보내기 꼴로 뽑아 세션 시작(내보내기 단계 생략). 쓰기는 여전히 1번 결과 JSON → 미리 보기. 필요한 것: nb.py `from-backup` 명령(백업의 `num.i.<과목>.*` + 기본 자료 seed 합치기 · s0 = 저장된 스토리 지문 — num.js `hsh`와 같은 FNV-1a 36진수).
3. **맥 로컬 폴더 다리** — 맥 세션에서 `~/Downloads/JBL넘버링_<과목>_*.json` 가장 최신 내보내기를 찾아 바로 시작 · 결과를 `~/Downloads/JBL가져오기_…json`으로 저장 → JBL에서 파일 고르기만. (브라우저 파일 접근 권한·경로는 사용자 확인 뒤.)
4. **JBL 쪽 받기 개선(그때 최소한으로)** — 가져오기 창에서 '새 스토리만 자동 적용' 같은 사용자 설정 · 결과 파일 이름의 세션 이름으로 이어하기 표시. 충돌·바꿈은 늘 사람이 고름(자동 적용 금지).
5. **(먼 미래) 동기화 통로** — 개인 비공개 저장소·클라우드 파일 등 사용자 인증이 있는 통로로 결과를 올리고 JBL이 그걸 미리 보기로 불러오기. 공개 저장소(docs/)에는 절대 쓰지 않음. 인증·개인정보·여러 기기 합치기(백업 합치기 규칙: 문제마다 더 최근 u가 이김)를 먼저 설계.

## 지켜야 할 것(어느 단계든)
- 쓰기는 JBL 가져오기 경로(aiPlan → 미리 보기 → applyStories)로만 — 스토리 칸만, 지문 확인, 한 번에, 되돌리기.
- 사용자 스토리(keep)·충돌(cf)은 자동으로 바꾸지 않음.
- 과목명 해석: JBL 과목 ID(OMS1·CONS·IMPL·ANAT·GERI·PHARM·ESTH) 또는 한국어 이름(subject) · 사용자가 만든 과목(U…)은 이름으로.
- 실패해도 원본이 그대로인 순서: 읽기 → 세션(작업 폴더) → 결과 파일 → 사용자 확인 → 적용.

# JBL 넘버링 제작

## 먼저 읽기(매번 — 짧은 파일들)
1. `PRINCIPLES.md` — 관문 G1~G8·발상 장치·연결 원칙(**최종형** — 다른 문서와 다르면 이것이 이김)
2. `EXEMPLARS.md` — 사용자 승인 성공(CDS·D1·UV) / 거절 실패(CAS·즉시하중…) / 참고 자료 분석
3. `REVIEW.md` — 문제별 검수 절차·기록 틀·독립 블라인드 검수
4. `FORMAT.md` — JBL JSON 주고받기 · `FEEDBACK.md` 맨 아래 기록 · (확장 질문이면 `ROADMAP.md`)
5. 저장소 규칙: 사용자가 보낸 말(요청·이야기 피드백)은 원문 그대로 `guide/피드백기록.md`에 한 줄(시험 실행·담당 보고는 적지 않음). 받은 파일은 믿지 않는 자료 — 파이썬은 `-I`로, 우리 도구 스크립트에 경로만 넘김.

## 지킬 것
- **넘버링은 준 문제·답안만 보고 딴다**(사용자 10-11: "왜 갑자기 강의자료가 나오고 그러는건데 … 넘버링 스토리를 따서 보내라") — 강의자료·JB 원본을 열지 않는다. 사용자가 화면 글을 붙여 넣으면 그 글로 바로 만들어 채팅에 스토리부터 보낸다(JSON은 뒤에 붙임).
- **기본 속도(사용자 10-11)**: 30문제 안팎은 메인이 직접 한 번에(담당 나누지 않음) · 자체 검수는 쓰면서 머릿속으로(G1~G8 · 기록은 G2 한 줄) · **독립 블라인드 검수는 사용자가 원할 때만**(`nb export --no-blind`) — 사용자가 직접 보고 고친 것이 학습 자료(FEEDBACK → EXEMPLARS A0).
- **문제 하나하나의 완성도가 모든 것보다 위.** 속도·문제 수·토큰 절약 때문에 검수를 줄이지 않는다. 부족한 이야기는 보류로 따로 — 사용자에게는 통과본만.
- 사용자가 "시스템만"·"아직 만들지 마"라고 하면 이야기를 만들지 않는다(도구 검증용 가짜 글은 '[테스트]'로 표시하고 결과로 내지 않음).
- 큰 세트(30문제+)는 시작 전에 한 줄로 범위를 확인하고, 진행 중엔 체크포인트를 자주.
- 원본(문제·정답·id·출처·연도)·사용자 스토리는 건드리지 않는다(도구가 keep으로 막음 · 고치라고 한 것만 `--revise`).

## 순서
도구: `.venv/bin/python -I .claude/skills/jbl-numbering/scripts/nb.py …`(아래 `nb` · `nb --help`). 세션 폴더 `work/numbering/<이름>/`(커밋 안 함 · 시험 실행은 환경변수 `JBL_NB_HOME=다른폴더`로 따로).

0. **요청 꼴 → 입력 고르기**(묻지 않고 바로):
   | 사용자 말 | 입력 | 기존 스토리 |
   |---|---|---|
   | "○○(과목) 넘버링 따줘"·`/jbl-numbering OMS1` (파일 없음) | `scripts/site_export.py <SID>`(사이트 JB 문제 · 기본 '서술형·넘버링형만' — 사용자 JBL 목록과 같은 꼴) · 강의만이면 `--lec 이름 일부` | 안 보임 → 전부 새로 · JBL이 가져올 때 이미 스토리 있는 문제는 '충돌'로 빼서 덮어쓰지 않음(그대로 안내) |
   | JBL 내보내기 파일을 줌 | 그 파일 | `story`·`s0`로 보호(keep) · "다듬어 줘"면 `--revise all`(그 스토리를 보고 고침) |
   | 화면 글을 붙여 넣음 | `site_export` 결과에서 그 문제들만 골라 세션 | 붙인 글에 스토리가 있으면 그 문제는 keep(고치라면 revise) |
   | "n번 좋아/별로야" | 피드백(6) | — |
   과목 코드: OMS1 구강외과1 · CONS 보존 · IMPL 임플란트 · ANAT 해부 · GERI 노인 · PHARM 약물 · ESTH 심미.
1. **받기** — 사용자가 JBL 내 넘버링 사이드바 'ChatGPT로 내보내기'로 받은 .json(또는 채팅에 붙인 JSON — 파일로 저장해서) 또는 0의 `site_export` 결과.
   `nb start 파일.json --name <과목_날짜>` → 문제 수·보호(keep) 수 확인. 고치기를 부탁받은 기존 스토리만 `--revise id,id`(또는 all).
   이어서 하는 거면 `nb status 이름` 또는 `nb start --from 이어하기.json`.
2. **문제마다(한 번에 하나 — 끝내고 다음)** — `nb next 이름` → PRINCIPLES 3절 순서대로 분해 → 단서 캐기 → 전제 3개+ → 초안 → REVIEW 1절 자체 검수(G1~G8, G2는 실제로 적어 봄) → 결함이면 원인 이름 붙이고 전제부터 재창작 → 판정.
   통과: 이야기를 파일로 쓰고 `nb save 이름 ID --status pass --story-file s.txt --review-file r.txt`(도구가 괄호 원문 포함·길이·빈 괄호를 검사 — 오류면 저장 안 됨, 경고는 다시 봄).
   보류: `nb save 이름 ID --status hold --story-file best.txt --review "막힌 관문·원인"`.
   관련 문제(도구가 보여 줌)와의 연결은 PRINCIPLES 4절 조건일 때만, 간섭(같은 단서 말)은 항상 확인.
3. **독립 블라인드 검수(필수)** — 통과 후보 10~15개마다 `nb blind 이름` 출력(아직 검수 안 한 통과본 · 정답 없음)을 새 Agent에게(REVIEW 3절 지시문 그대로) → 정답과 견줘 `nb blindres 이름 id,id --ok|--fail --note …`. 실패는 자동으로 다시 todo → 재창작. `nb export`는 독립 검수 통과만 냄.
4. **중간 저장** — 문제를 저장할 때마다 state.json이 바로 저장됨. 멈추거나 세션이 끝날 것 같으면 `nb checkpoint 이름` → 그 파일을 사용자에게(클라우드는 work/가 사라짐).
5. **내기** — `nb export 이름 --print` → 결과 파일 `out/JBL_가져오기_….json` + `out/hold.md`. `nb verify 이름 결과.json`이 통과해야 낸다.
   사용자에게: ① 결과 파일(클라우드 세션은 SendUserFile, 맥은 경로) ② 같은 JSON을 ```json 코드 블록 하나로(복사 → JBL '결과 가져오기' 칸에 붙여 넣기 → 미리 보기 → 적용) ③ 짧은 요약: 통과 n · 보류 n(이유 한 줄씩) · 보호(기존 스토리) n · "통과는 제 검수 기준이고, 승인은 직접 봐 주셔야 확정돼요".
   쓰는 법 안내(처음 한 번): JBL 내 넘버링 → 사이드바 'ChatGPT 결과 가져오기' → 붙여 넣기(또는 파일) → 미리 보기 → '새 스토리 n개만 적용'. 이미 스토리가 있던 문제는 '바꿈·충돌'로 따로 나오고 고르지 않으면 안 바뀜.
6. **피드백** — 사용자가 이야기에 대해 말하면 `FEEDBACK.md` 절차 그대로(원문 기록 → `nb feedback` → 사례·원칙 갱신 → 남은 문제에 다시 적용 → 스킬 파일 커밋·푸시). 거절된 문제는 같은 이야기를 다시 내지 않고 전제부터 새로.

## 큰 세트에서
- 품질이 먼저: 한 담당(주 대화든 Agent든)이 문제를 하나씩 끝까지. 문제 하나를 여러 담당이 나눠 쓰지 않음.
- 나눠 맡길 때는 강의 단위로 **세션을 따로**(입력 JSON을 강의 묶음 15~25문제로 나눠 `OMS1_g1…` 세션마다 한 담당 — 한 세션 state.json을 여럿이 동시에 쓰면 저장이 사라짐). 담당마다 이 스킬 파일(SKILL·PRINCIPLES·EXEMPLARS·REVIEW)만 읽게, 강의자료·JB 원본·웹은 보지 않게. 이미 승인된 장면 목록을 주고 다른 문제에 다시 쓰지 않게.
- 블라인드 검수는 언제나 만든 담당과 다른 새 담당: 메인이 `nb blind 세션 > 파일` → 검수 담당은 그 파일만 읽고 보고 → 만든 담당(이어서)이 정답과 견줘 `nb blindres` · 실패만 재창작 → 재창작분만 다시 블라인드(새 담당) → 2번째에도 실패면 보류.
- 끝에 세션마다 `nb export` + `nb verify` → `scripts/merge_out.py 결과들 --out 합본.json --order 원본.json` 하나로 → 승인돼 있던 결과도 합본에 넣음 → 파일 하나를 사용자에게(코드 블록은 길면 생략하고 파일만).
- 토큰은 문제 글·기록을 짧게 하는 데서 아끼고, 발상·비평·재창작 생각은 줄이지 않는다.

## 확장(이번엔 없음)
`/jbl-numbering 과목명`은 문제 목록까지는 됨(0의 `site_export` — 사이트 JB 문제). 사용자 브라우저 저장(기존 스토리)을 직접 읽고 쓰는 것은 `ROADMAP.md` 설계만 — 반영은 지금도 JBL '결과 가져오기'(파일)로만 한다.

# JBL 업데이트 — 한 번에 완성본까지

심미치과학(ESTH)은 정리본을 만든 뒤 사용자 지적 수십 번(필사본 반려 → 카드형 → 검토 3회 → 줄바꿈 3회 → 번호·들여쓰기 → 표 → JB 해설 5회 → 🔑⚡ 3회 …)을 거쳐 지금 모양이 됐다. 이 스킬은 그 **모든 회차를 처음부터 차례로 한 번에** 돌려, 사용자가 다시 지적하지 않아도 되는 완성본을 만든다.

## 먼저 읽기(매번)
1. `CLAUDE.md` · `.claude/skills/jbl-update/RULES.md`(**최종형** — 문서끼리 다르면 이 파일이 이김, 13절 = 이미 받은 결정) · `QA.md`(사용자 눈 점검표) · `AGENTS.md`(담당 지시문 틀)
2. `guide/피드백기록.md` 맨 아래 20줄과 '10-15 (26 JB 7개 …)' 블록 전체(1~9번 — 새 연도 묶음의 기준) · `guide/과목노트_<SID>.md` · `guide/정리본_원칙.md` · 클라우드면 `guide/인수인계_클라우드.md` A-2(자료 받기)·A-4(주의)만(A-3 '남은 일'은 10-03에 끝남 · A-2의 'annot·tables·pred는 tools/에서 직접'·A-4의 'build_all 1~2시간'보다 이 스킬의 D·E(parts)·F(직접)·G(full_check)가 이김) · 이어 가는 중이면 `guide/handoff/UPD_<MMDD>_진행.md`
3. 사용자 메시지는 **원문 그대로** `guide/피드백기록.md`에 한 줄(작업 중 새 지시가 와도 매번). 새 규칙이면 RULES.md·QA.md에도(다음에 같은 지적이 없게), 새 결정이면 RULES 13절에.

- **묻는 것**: RULES 13절에 없는 새 결정만(강의 신설·삭제·교수 변경, pptx만 온 자료, 자료끼리 모순). B단계 직후 **한 번에 묶어**(2~3안씩) 묻고 답을 기다리는 동안 다른 강의를 진행. 답은 피드백기록·RULES 13에.

- **강의 하나라도 끝나면 중간 배포**(사용자 10-22 "먼저 한 강의라도 작업 끝나면 중간 배포해줘!" · 10-23 "중간중간 적절한 시점에 강의자료 하나라도 완성되면 중간배포"): 단위 = **과목**(그 과목의 바뀐 강의가 모두 검토 회차(등급표)를 끝냈을 때) — 같은 과목에 아직 작업 중인 강의가 있으면 ⓐ 배포된 적 없는 새 강의 → 아래 '○○ 빼고 중간 배포'(JBL_SKIP_LECS) ⓑ 이미 배포된 강의의 갱신 → 그 강의가 검토를 끝낼 때까지 기다림(섞여 나가지 않게). 시점 = 검토 회차 끝(내용 확정 — 10-23 무인 해석: 이 사용자는 빨리 보기를 원함 · 다듬기(F)·QA는 최종 배포에서 — 사용자 확인 중, A안 = 다듬기·QA까지 끝낸 뒤 배포). 중간 배포 뒤 F는 배포된 판을 고치는 회차 — 이미 나간 줄의 낱말을 바꾸면 보고에 · 최종에 legacy_restore(`--rev <갱신 전 origin/main>`)로 위치 잃음 확인. 중간 배포 전 검사: 작성 보고 '개인 연락처 쪽' → NOIMG_PAGES · QA 63·68 · merge → 그 과목 build4 → check_lec·years·eyears·abbr·unote·yearprof·link_audit·pred_check·fc_carry·scan_render → rehub → verify → main(H 푸시 절차) · 첫 배포 전 진행 파일에 `git rev-parse origin/main`(갱신 전 기준 — 최종 fc_carry·legacy_restore 비교도 이 커밋) · 보고에 '몇 차 중간 배포 · 어느 강의'.
- **단계별 배포**(사용자 10-15 7번 — 자료·JB → 예상문제 → 허브 기능 → 저장 공간): 단계마다 full_check → 배포. 배포 전 `git rev-parse origin/main`을 진행 파일에 적음(되돌릴 기준 · legacy_restore `--rev`). 검증 안 된 것은 작업 브랜치 WIP 커밋만(main 금지).
- **'○○ 빼고 중간 배포'**(10-17 ESTH BOOK — 사용자 '교과서 정리본 빼고 중간 배포'): **배포된 적 없는 새 강의만**(이미 배포된 강의를 빼면 사이트에서 통째로 사라짐 — 갱신 중인 기존 강의는 갱신 전 판 그대로 두거나 기다림). `export JBL_SKIP_LECS=<KEY>[,<KEY>]` 뒤 build4와 `sh tools/full_check.sh` 모두(lecparse ORDER에서 강의 · build4 SKIPL로 그 강의 예상(PRED k)·표(tables k)도 빠짐 · 변수는 전 과목에 걸림 — 키가 다른 과목과 겹치지 않는지 한 줄 확인). main에 올리기 전 팩 확인: `.venv/bin/python -c "import sys; sys.path.insert(0,'tools'); import jblpaths as J; p=J._load_js('docs/packs/<SID>.js'); K='<KEY>'; print([x['k'] for x in p['lect'] if x['k']==K], sum(x.get('k')==K for x in p['preds']), sum(x.get('k')==K for x in p['tables']))"` = `[] 0 0` · `docs/packs/<SID>.img.<KEY>.js` 없음 · 다른 강의 파일의 `[[<KEY>:n]]` 칩은 SKIP으로 안 빠짐(`grep -c '\[\[<KEY>:' tools/<sid>/*.txt` — 그 강의 몫 밖이 0이 아니면 보고에 · 빼야 하면 그 칩을 넣기 전 커밋으로 worktree 빌드). 진행 파일 맨 위에 'SKIP 중 <KEY>(배포 커밋)' — 그 강의가 끝날 때까지 H '빼고 배포 중' 줄을 지킴.
- 단계마다 짧게 보고(한국어). "얼마나 남았어?"엔 단계·남은 담당 수로 분 단위 추정(작성·검토 회차 각 15~25분, 전 검사 40분).

- **담당이 사용 한도(429)로 멈추면**(10-09 두 번): ⓐ 채운 지시문은 띄우기 전에 `work/_tmp/agents/<담당 이름>.md`에 저장하고, 진행 파일 '진행 중 담당'에 이름·지시문 경로·기준본 저장 시각을 적음 ⓑ 한도 메시지의 풀리는 시각 + 5분에 `send_later`(메시지 '진행 파일 guide/handoff/UPD_<MMDD>_진행.md 읽고 멈춘 담당 <이름들> 다시 띄우기' — 5시간 예약과 별개, 울리면 지움) ⓒ 다시 띄울 때 같은 지시문 + 한 줄 '앞 담당이 한도로 멈춤 — 보고 파일과 text_diff·annot_diff(기준본 그대로 — 다시 --save 하지 않음)로 이미 한 것을 확인하고 남은 것만'.
- 담당이 끝날 때마다 **그 담당 파일만** 커밋·푸시(작업 브랜치). parts(work/)는 커밋되지 않으니 회차 끝 `merge_parts` 뒤 `tools/<sid>/annot·tables·pred` 커밋. docs/는 빌드가 끝난 뒤에만. `work/`·`materials/`·`jb/`·`reference/`는 절대 커밋하지 않는다.
- 오래 걸리는 명령은 Bash `run_in_background`로(`cmd &` 금지 — 호출이 끝나면 같이 죽음). 기다릴 땐 `until …; do sleep; done` 한 번.
- **parts ↔ tools는 한 방향만**(10-10 — `merge_parts`는 parts 폴더의 **모든 강의 조각**으로 tools/<sid>/annot·tables·pred를 덮음 → tools를 직접 고친 뒤 돌리면 끝난 수정(NEW 26·필기 표시·표)이 소리 없이 되돌아가고 빌드·검사는 통과함): 한 과목 안에서 parts 담당(D 새 강의·E·F ≤5 모드)과 tools 직접 담당(F 표준 D1~D2b·B3 표시·QA 직접 수정)을 동시에 돌리지 않는다. tools를 직접 고친 뒤에는 그 과목 parts가 낡음 → parts를 다시 쓰기 전 반드시 `split_parts <SID> --force`. merge_parts 직전: 마지막 split 때 커밋(진행 파일에 적어 둠) 뒤로 `git log --oneline <그 커밋>..HEAD -- tools/<sid>/annot.txt tools/<sid>/tables.txt tools/<sid>/pred.txt`가 비었는지(아니면 merge 금지 — 고친 조각만 손으로 옮기거나 다시 split). 도구도 막음: split_parts가 `work/<SID>/parts/.stamp`(그때 tools 3파일 sha1)를 쓰고 merge_parts(·--check)는 지금 tools가 다르거나 .stamp가 없으면 ✗ '낡은 조각'으로 멈춤(`--stale-ok`는 알고 덮을 때만). 10-10 기준 7과목 모두 parts 낡음(.stamp 없음 — 다음 parts 작업 전 split_parts --force).
- 허브 코드 담당을 worktree로 여럿 띄우면(10-15 S1c·S3·S4) 같은 파일(num.js·shell.html·build4)을 고치는 담당은 차례로 합침: 먼저 끝난 것을 합쳐 full_check → 다음 것은 그 위에 `git merge`(충돌 = 두 쪽 다 살림 · NUMV는 build_num이 다시 씀) · 허브 화면 담당 지시문에 한 줄 — '새 CSS·화면은 디자인 v3(정리본_원칙 7-1 첫 줄 · SPEC '디자인 v3' · shell.html 맨 끝 v3 묶음 뒤에 — 바탕 회색·카드 흰색·누르는 것 먹색·폰 위 고정은 탭 한 줄) 위에서 v2 규칙도 지킴: 누르는 것 --brand · 의미 색 토큰(--exam-*·--pred-*·--e26) · 과목 색(--sj·sjColor)은 메뉴 점·지금 탭 밑줄·선택 막대 말고 금지 · 세리프·새 단추/칩 꼴 금지 · 단추 이름 답 보기 → 해설 더 ▾ → 답 접기 ▲ · ⭐ 기출 / ★ 북마크' → full_check. worktree 담당이 메인 데이터를 빌려 빌드했으면 그 파일은 커밋하지 않게(빌린 목록 파일).
- 한 파일은 한 담당만. 담당 수: 바뀐 강의 ≤3이면 D1·D2도 강의마다 1명, 그보다 많으면 강의 묶음 2개(3~4강의씩).

1. 원문 그대로 `guide/피드백기록.md` → 2. 어느 파일을 어떻게 고칠지 한 문단(방향이 갈리면 2~3안) → 3. 고치고 빌드·검사·스크린샷 → 4. 같은 종류를 **모든 과목**에 적용(작으면 바로, 크면 묻기).
5. **스킬 갱신(빠뜨리지 않음 — QA 새 번호는 늘 번호 목록 끝 = '스크린샷으로 꼭 볼 것' 절 앞에 붙이고 AGENTS E의 '지금 1~N'도 고침)**: RULES.md(새 규칙 — ✗/✓ 예는 사용자 원문 그대로) · QA.md(새 점검 항목 — 확인 방법까지) · RULES 13(새 결정) · AGENTS.md(그 규칙을 지켜야 할 담당 지시문) · 이번에 쓴 BRIEF가 있으면 `guide/handoff/`(다듬기 BRIEF는 `review_final/`)에 두고 AGENTS(그 담당 틀)·SKILL에서 가리킴 · 새 검사 스크립트·테스트는 `tools/full_check.sh`에.
6. **스킬 자기점검**(커밋 전): (점검 파일: 10-23까지 11·12회차 = `work/_tmp/skill_audit_1023.md`·`_1023b.md` · 13회차 = `skill_audit_1024.md`(디자인 v3) · 14회차 = `skill_audit14_*` · 15회차 = `skill_audit15_1026.md`(동기화 쓰던 그대로·유형 줄·예상 줄) → 다음 `skill_audit16_<MMDD>.md`) 독립 담당 1명에게 "피드백기록.md 전체(특히 이번 것)와 지금 가장 최신 정리본(이번에 고친 강의)을 보고 — 이 스킬(RULES·QA·AGENTS·SKILL)만 따라 새 강의를 만들면 지금 품질이 나오는가, 빠진 지시·모순·틀린 경로는 없는가"를 보고만 하게 하고(`work/_tmp/skill_audit<n>_<MMDD>.md` — 앞 회차 파일을 덮지 않게 다음 번호 · 10-17 판 `skill_audit10_1017.md` = 10회차 → 다음 11), 걸린 것을 고친다.
7. 사용자 보고 끝에 한 줄: "스킬에도 반영: RULES n절·QA n번 …".

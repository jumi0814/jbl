> **10-07부터는 스킬 `.claude/skills/jbl-update/SKILL.md`가 이 절차 + 그 뒤 사용자 지적으로 생긴 모든 회차(검토 3회·줄바꿈·번호·표·JB 해설·🔑⚡·QA)를 한 번에 돌린다.** 이 문서는 갱신 모드의 세부(맥 한 줄·apply_map26·표시 보존)로 남긴다.

사용자 요청(10-03): "26년도 업데이트된 강의자료들을 … 내 로컬 폴더에 따로 26년도 자료를 넣어놓으면 너가 각 과목별 25년도 강의자료 정리본을 26년도에 맞춰서 업데이트 … 이미 내가 필기하거나 메모, 하이라이트 친 강의 정리본, 북마크, 중요표시 등등 이런 데이터들은 앞으로 각종 업데이트 및 개선점이 이뤄져도 그대로 유지되었으면 좋겠어!"

## 한눈에 — 사용자는 두 가지만
1. **맥**: 26년도 PDF를 `jbl/materials/<과목명>/`에 넣는다(파일 이름은 받은 그대로 — 예: `260918_서덕규_….pdf`). 25년도 파일은 지우지 않아도 된다(최신 연도를 자동으로 고름).
2. **맥 터미널**(jbl 폴더에서): `git pull && sh tools/push_materials.sh` — 쪽 이미지·텍스트·필기·OCR을 뽑아 **새로 넣은 파일(cloud-materials 브랜치에 아직 없는 것)의 추출본만** 클라우드 작업용 브랜치에 올린다(이미 올린 자료·원본 PDF는 올리지 않음). 과목 몇 개만이면 `sh tools/push_materials.sh CONS GERI`, 올릴 목록만 먼저 보려면 `sh tools/push_materials.sh --dry`.
3. 그다음 클라우드 대화창에 **"26년도 자료 반영해 줘"** 한 줄. 나머지(대조·정리본 수정·검토·빌드·검증·배포)는 Claude가 한다.

## Claude가 하는 일(클라우드)
1. `sh tools/cloud_setup.sh` → `sh tools/cloud_materials.sh`(새 추출본 받기).
2. **자료 표 만들기**: `work/<SID>/mat/index.json`에서 새 파일 찾기 → 강의 주제마다 가장 최신 연도 파일을 고른 표를 사용자에게 먼저 보여 줌(강의가 새로 생기거나 없어졌으면 그때만 물어봄).
3. **연결 바꾸기**: `tools/matx.py`의 SRC 표·`tools/<sid>/subject.py` LECMAP(강의 키 ↔ 26 파일), 정리본 머리의 연도·파일명·쪽수 · `work/<SID>/lec/<폴더>` 연결을 새 파일로(파이썬 몇 줄 — PDF 없이 가능).
4. **25 ↔ 26 쪽 대조(강의마다 한 명씩 병렬)**: 26 슬라이드를 1쪽부터 끝까지 넘기며 — 같은 쪽(쪽 번호만 밀림) / 바뀐 쪽(문구·수치·표) / 새 쪽 / 빠진 쪽 을 표로. 26 필기의 '강조'·'시험문제' 메모를 새로 찾음.
5. **정리본 고치기 — 표시 보존 원칙대로**(아래). 쪽 번호(`p.`·`F:` 그림 쪽)는 26 쪽으로 다시 매기고, 바뀐 사실만 고치고, 새 쪽은 알맞은 카드에 항목·그림·⭐를 더함. JB ⭐는 그대로 두되 26 근거 쪽으로 바꿈(annot `[[KEY:쪽]]`).
6. **독립 검토**(다른 검토자) — 26 자료 ↔ 원고 역대조 · ⭐ ↔ JB 답 · 빨강 비율 · 형식.
7. `sh tools/build_all.sh`(7과목) → verify · audit · 테스트(특히 **legacy_restore · kt_migrate · aidlock_test** = 표시 이관) → main 배포 → 사이트 확인 → 과목·강의별로 무엇이 바뀌었는지 보고.

2. 강의 키를 새 파일로: `tools/matx.py` SRC에 새 폴더(예 C10i: '260922_') · subject.py LECMAP `<KEY>` = 26 · `<KEY>5` = 25 · IMG_ALIAS `<KEY>5 → <KEY>` · work/<SID>/lec/<폴더> 링크 · (쪽 수가 바뀌면 FORCE_PAGES)
3. 작성자(강의마다 1명, `guide/handoff/UPD26_BRIEF.md`) → `work/<SID>/upd26/<KEY>_map.json` + 원고
4. `tools/apply_map26.py <SID> <KEY>`(한 번만 — .applied 표시) → `tools/split_parts.py <SID> --force`(그 과목 강의가 다 옮겨진 뒤)
5. 검토자(작성자와 다른 1명, `guide/handoff/UPD26_REVIEW_BRIEF.md`) → `tools/merge_parts.py <SID>`
6. 다른 강의 파일이 바뀐 키를 가리키는 곳(맨글 'p.N'·F:·#TBL src)을 grep으로 확인해 손으로
- 배운 것: apply_map26의 맨글 p.n 옮기기는 'JB 참고 p.N'·다른 강의 쪽·25 필기 쪽까지 옮김 → 검토자가 꼭 되돌림. **25 필기 인용은 `[[<KEY>5:n]]`**(26 쪽 이미지에는 25 필기가 없음). 26 PDF 필기는 다른 학생·학습부 메모일 수 있음 → "26 필기"로 구분.
- 결과: 8강의 모두 26 슬라이드가 25와 거의 같음(쪽 1~2 이동·중복 쪽 정리) — 26 필기의 시험 예고·강조를 덧붙인 것이 주된 변화. IMPL PRO는 김성균 PPT 그대로(박지만 대강), PHARM ACU는 우경미 PPT 한국어판(김우진 강의).

## 사용자 표시를 지키는 원칙(모든 업데이트·개선에 공통 — 원칙 문서에도 반영)
지키는 데이터: 형광펜·빈칸(ann), 메모(memo), 강의 북마크(lbm), 카드 북마크(cbm), ✓ 다 봄 기록(done), JB 채점·중요(★)·틀림(mk), 플래시카드(fc), 자동 빈칸 규칙(autoRule), 공부 시간(time·tseg·tedit…).
- **카드 id 고정**: 카드마다 aid가 `tools/<sid>/aid_lock.json`에 잠겨 있어, 제목이나 문장이 바뀌어도 같은 카드로 이어짐(빌드가 맞춤). 그래서 **카드를 나누거나 합치거나 순서를 크게 바꾸지 않는다** — 꼭 필요하면 새 카드를 덧붙이는 쪽으로.
- **문장은 덧붙이기 > 고치기 > 지우기**: 형광펜·빈칸은 그 글자와 앞뒤 문맥으로 다시 찾아 붙는다. 바뀐 낱말만 고치고 문장 통째 재작성은 피함. 사라진 문장에 붙어 있던 표시는 지우지 않고 '🖍 내 표시 모아보기 → ⚠ 위치를 잃은 표시'에 옛 글과 함께 남음.
- **강의 키·JB 문항 id는 바꾸지 않는다**: 메모·강의 북마크는 강의 키에, 채점·중요·플래시카드는 JB 문항 id(`jb_lock.json`)에 붙어 있음.
- **저장 형식은 새 키만 더한다**: 옛 저장 키를 지우거나 덮어쓰지 않음(이관이 필요하면 옛 값을 남긴 채 새 키로). 이관 전에는 허브가 자동 백업을 만듦.
- **사용자도 한 번**: 큰 업데이트 전에는 💾 백업 창 → [백업 파일 보내기]로 파일을 하나 받아 두면 어느 기기에서든 되돌릴 수 있음(합치기·교체·되돌리기).
- 매 빌드 뒤 확인: `tests/legacy_restore.py`(옛 판의 표시가 새 판에서 같은 글자에) · `kt_migrate.py`(원고가 바뀐 뒤 이관) · `aidlock_test.py`(카드 id 유지) · 🖍 모아보기의 '위치 잃음' 수가 늘지 않았는지.

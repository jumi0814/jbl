## 이미 고친 렌더러 규칙(코드 — 다시 고치지 말 것)
- JB 주석 긴 줄: ' / '를 대시(' — ')보다 먼저 나눔 → 'A — 설명 / B — 설명'이 바르게 둘로.
- ' / '로 나뉜 조각이 '사실 문장'(' = '·' → '·': '·' — '·안에 ' · ' 나열)이면 가로로 잇지 않고 한 줄씩(🔑 'Lambdoid … / Positional …' 해결). 낱말뿐인 짧은 나열은 가로(격자) 그대로 — 사용자가 좋다고 한 모양.
- 영어 소문자 낱말 둘 사이 ' / '(앞이 한글·괄호·문장 첫머리)는 '또는'으로 보고 나누지 않음('각각 frontal / posterior plagiocephaly' 해결).

## 할 일
1. 덤프 `work/review_breaks2/<SID>_<영역>.md`(영역 lec = 정리본 학습·정리표·강의 비교표 / jb = JB 카드(대조·해설·답·주변부)·예상문제·과목 비교표·기출 한눈표)를 **처음부터 끝까지 한 덩어리도 빼지 않고** 읽는다(Read를 여러 번 — offset/limit). ⚑ 의심 덩어리만이 아니라 나머지도 전부.
   덩어리 = 화면에서 줄(•)로 나뉘어 보이는 모습 그대로. '[머리]'는 굵은 머리말, '‣'는 그 아래 줄.
2. 줄마다 판단: (가) **나뉘어야 하는데 안 나뉨** — 서로 다른 대상·사실 둘 이상이 한 줄에 붙음(사용자 예 'Ms Positional', '…anteriorly / Lambdoid …') · (나) **엉뚱한 곳에서 나뉨** — 한 대상/한 문장이 두 줄로 찢김('frontal' | 'posterior plagiocephaly로'), 머리말과 설명이 엇갈려 붙음, 조각이 '— …'·'→ …'·조사·소문자로 시작 · (다) 덩어리에 안 잡히는 **긴 한 줄**(나뉘어야 할 서로 다른 사실이 · 로만 이어짐)도 원고에서 찾아본다.
3. 고치는 곳: 화면 글자로 원고를 찾는다(`grep -rn '<조각 앞 15자>' tools/<sid>/`). 원고 파일:
   - lec 영역 → `tools/<sid>/lec_*.txt`·`tools/<sid>/tables.txt`만
   - jb 영역 → `tools/<sid>/annot.txt`·`tools/<sid>/pred.txt`만 (lec 영역 담당과 파일이 겹치지 않음 — 다른 파일 절대 수정 금지)
   고치는 법(글자 최소 변경 — 사용자 형광펜·빈칸이 글자에 붙어 있음): 구분 기호만 — 다른 대상 사이는 ` / `, 한 대상 안은 ` · `, 낱말 사이 '또는'은 `/`(띄우지 않음), 머리말은 `X: `. 필요하면 한 줄을 글자 그대로 두 줄(`-`)로 나눔. 낱말·`{r:}`·`==`·`**`·순서는 그대로.
   - JB 답(원문)은 글자 불변 — 원문 쪽 줄바꿈 문제는 고치지 말고 보고서에 '원문(렌더러) 필요'로.
   - 렌더러로만 고칠 수 있는 일반 패턴은 고치지 말고 보고서 '렌더러 제안'에(예: 어떤 기호 조합에서 늘 틀림).
4. 확인: 고친 줄은 `.venv/bin/python tools/dump_breaks.py <SID> <강의키>`(lec 원고 줄 화면 조각)로 바로 확인 가능. annot·pred는 다음 빌드에서 확인하므로 기호 규칙을 지켜 정확히.
